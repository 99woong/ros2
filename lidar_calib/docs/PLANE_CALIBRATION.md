## 1. 배경 및 문제 정의

### 센서 구성

| 항목 | 값 |
|------|----|
| LiDAR 모델 | Ouster OS1-32 |
| LiDAR1 위치 (world) | (0, 0, 5 m) — 전방 기준 센서 |
| LiDAR2 위치 (world) | (−15, −3, 5 m) — 후방 교정 대상 |
| 센서 이격거리 | X축 15 m, Y축 3 m |
| 목표 오차 | 위치 ≤ 10 mm, 각도 ≤ 0.5° |

### 왜 구/큐브 방식이 실패하는가

OS1-32의 수직 빔 간격은 약 1.45°이다. 타겟까지의 거리에 따라 빔 간격이 아래와 같이 벌어진다.

```
수직 빔 간격(mm) = tan(1.45°) × 거리(m) × 1000
```

| 거리 | 수직 빔 간격 | 200 mm 구에 맞는 빔 수 |
|------|-------------|----------------------|
| 4 m  | ~101 mm     | 2개 — 아슬아슬 가능   |
| 8 m  | ~202 mm     | 1개 — 불안정         |
| 15 m | ~380 mm     | 0~1개 — RANSAC 수렴 불가 |

수평 해상도(1024 mode, 15 m 기준 ~92 mm)는 여전히 양호하지만,  
수직이 희소하면 구 중심 추정 RANSAC이 퇴화(degenerate)한다.

**결론**: 15 m 이격 환경에서 소형 타겟(구·큐브)은 달성 목표를 충족할 수 없다.

### 왜 대형 평면 패널이 효과적인가

1.5 m × 1.5 m 패널에 맞는 포인트 수 (15 m 거리 기준):

```
수직: 1500 mm ÷ 380 mm ≈ 4 scan ring
수평: 1500 mm ÷  92 mm ≈ 16 pts/ring
합계: 약 64 pts/패널
```

수십 개 포인트로 평면(ax + by + cz + d = 0)을 RANSAC 피팅하면  
**법선 벡터와 평면 위치를 수 mm 정밀도로 추정**할 수 있다.

## 2. 캘리브레이션 원리

### 2.1 핵심 제약: 두 센서가 동일한 면을 봐야 한다

```
                      ┌──────────┐
                      │  패널 앞면  │ ← 반사 면
                      └──────────┘
                         ↑   ↑
               L1 시선   │   │  L2 시선
          (0,0,5) ──────┘   └────── (−15,−3,5)
```

패널을 두 센서 **사이**에 배치하면 L1은 앞면, L2는 **뒷면**을 보게 되어  
법선 방향이 반대로 검출된다 → 캘리브레이션 불가.

**올바른 배치**: 패널을 AGV **한쪽 측면**(+Y 방향)에 배치하면  
두 센서 모두 +Y 방향을 바라보며 **동일한 앞면**을 관측한다.

동일면 조건은 다음 수식으로 검증된다:

```
dot(n, L1_pos − center) > 0  AND  dot(n, L2_pos − center) > 0
```

### 2.2 평면 표현

각 패널은 아래 두 값으로 표현된다:

- **법선 벡터** n̂ ∈ ℝ³ (단위 벡터, 센서 방향 통일)
- **중심 좌표** c ∈ ℝ³ (RANSAC inlier 무게중심)

### 2.3 solvePlanesToPlanes 알고리즘

3개 패널에서 각각 (n₁ᵢ, c₁ᵢ)와 (n₂ᵢ, c₂ᵢ)를 추정하고,  
T = (R, t) — LiDAR2 → LiDAR1 변환 — 을 구한다.

**Step 1: 법선 기반 Kabsch SVD → 회전 R**

```
H = Σᵢ  n₁ᵢ · n₂ᵢᵀ          (3×3 행렬)
SVD(H) = U S Vᵀ
R = V Uᵀ                      (det < 0 이면 반사 보정)
```

- 법선은 방향만 있는 단위 벡터이므로 translation 없이 순수 회전만 추정된다.
- 3개 패널의 법선이 서로 다른 방향을 가리키면 R의 모든 자유도가 결정된다.

**Step 2: 중심 기반 평균 이동 → 번역 t**

```
t = (1/N) Σᵢ  (c₁ᵢ − R · c₂ᵢ)
```

**Step 3: 지상 차량 구속**

AGV는 평지 주행 → roll ≈ 0, pitch ≈ 0 가정 적용:

```
R_final = Rot_z(yaw)              (roll·pitch 소거)
t_final = mean(c₁ᵢ − R_final · c₂ᵢ)
```

이를 통해 빔 커버리지 불균형으로 발생하는 미세 roll/pitch 오염을 제거한다.

**패널 매칭**: N개 패널에 대해 N! 순열 전수 탐색으로  
중심 잔차 + 법선 각도 오차를 최소화하는 대응 순열을 선택한다.

## 3. 알고리즘 동작 단계

```
누적 raw cloud (L1, L2)
        │
        ▼
┌─────────────────────────────────────────────┐
│  detectPanels (센서별 독립 실행)              │
│                                             │
│  1. VoxelGrid 0.05 m 다운샘플               │
│  2. Euclidean Clustering (tol 0.40 m)       │
│  3. 클러스터 크기 필터 [8, 3000]             │
│  4. 거리 필터 (> panel_min_distance)         │
│  5. RANSAC PLANE 피팅 (dist_thresh 0.05 m)  │
│  6. inlier ratio ≥ 0.65 필터               │
│  7. inlier bbox 크기 검사 (0.5×~1.85× sz)  │
│  8. 법선 flip → 센서 방향 통일              │
└─────────────────────────────────────────────┘
        │
        ▼ (PanelTarget × 3 per sensor)
┌─────────────────────────────────────────────┐
│  solvePlanesToPlanes                         │
│                                             │
│  1. 6가지 순열 전수 탐색                     │
│  2. 각 순열: Kabsch SVD(법선) → R           │
│  3. 중심 평균 → t                           │
│  4. 잔차 = Σ(중심오차 + 1−|cos(법선각)|)    │
│  5. 잔차 최소 순열 선택                     │
└─────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────┐
│  지상차량 구속 (Ground Constraint)           │
│                                             │
│  1. SVD 결과에서 yaw 추출                   │
│  2. R_final = Rot_z(yaw)                    │
│  3. t_final = mean(c₁ᵢ − R_final · c₂ᵢ)   │
└─────────────────────────────────────────────┘
        │
        ▼
  current_T_ 갱신 → TF broadcast → YAML 저장
```

## 4. 타겟 배치 위치

### 4.1 배치 원칙

| 원칙 | 이유 |
|------|------|
| 패널 3개를 AGV **한쪽 측면(+Y 방향)**에 배치 | 두 센서가 동일한 앞면을 관측 |
| 각 패널의 법선은 AGV 방향(-Y)을 향하도록 설치 | 동일면 조건 dot(n, sensor−center) > 0 |
| T1은 L1 가까이, T3는 L2 가까이 | 빔 해상도 최대화 |
| 패널 3개의 법선 방향을 약간씩 다르게 | 6DOF 회전 결정을 위한 법선 다양성 확보 |

### 4.2 권장 좌표 (world frame)

```
              +Y
              │
   +Y=5.5m    │        패널 배치 구역
   ┌──────────┼──────────────────────────────┐
   │   [T1]   │    [T2]          [T3]        │
   │  法n₁   │    法n₂          法n₃         │
   └──────────┼──────────────────────────────┘
              │
  (L1)        │                         (L2)
  (0,0,5) ───┼───────────────────── (−15,−3,5)
              │
              0                            −X
```

| 타겟 | 위치 (X, Y, Z) | 법선 방향 | L1까지 거리 | L2까지 거리 |
|------|--------------|---------|-----------|-----------|
| T1   | (−3, 5.5, 0.8) | (−0.35, −0.94, 0) | ~7.5 m | ~15.5 m |
| T2   | (−7.5, 6.0, 0.8) | (0, −1, 0) | ~10.4 m | ~12.4 m |
| T3   | (−12, 5.5, 0.8) | (+0.35, −0.94, 0) | ~13.4 m | ~9.4 m |

> **T1은 L1에 가깝게, T3는 L2에 가깝게** 배치하여 어느 센서도  
> 모든 패널을 최대 거리에서 보지 않도록 분산한다.

### 4.3 패널 설치 방향

패널은 **수직 직립** 설치를 권장한다.

```
측면도 (XZ):

 Z=5m  ●L1                           ●L2
       │  \     \        \     /      │
       │   \     \        \   /       │
 Z=2m  │    \  [T1]  [T2]  [T3]      │
       │                              │
 Z=0m  └──────────────────────────────
```

- 패널 하단: Z ≈ 0.1 m (지면 위)
- 패널 상단: Z ≈ 1.6 m (1.5 m 패널 기준)
- 패널 중심: Z ≈ 0.8 m

### 4.4 패널 각도 조정

법선 다양성을 위해 T1과 T3를 수평면에서 약 ±20° 기울인다.

```
상면도 (XY):

       T1 (−20°)     T2 (0°)     T3 (+20°)
        /──/           |──|          \──\
       /  /            |  |           \  \
      법선→             법선↓           법선→

  L2●                                      ●L1
```

패널 앞면(반사 코팅면)이 AGV 방향(−Y)을 향하도록 설치한다.

## 5. 테스트 절차

### 5.1 사전 준비

**장비 요구사항**

- 1.5 m × 1.5 m 역반사(retroreflective) 패널 3개
- 패널 거치대 (수직 직립, 높이 조절 가능)
- ROS2 Humble 환경, `lidar_calib` 패키지 빌드 완료

**환경 요구사항**

- 차량 정차 상태 (엔진 진동 최소화)
- 패널 주변 1 m 이내 장애물 없음
- 패널은 3개 모두 두 LiDAR의 시야각(±22.5°) 내에 위치

### 5.2 단계별 절차

#### Step 1: 패널 배치

4.2절의 좌표를 참고하여 패널 3개를 AGV +Y 측면에 설치한다.

```bash
# 레이저 거리 측정기로 패널-센서 간 거리 확인
# T1: L1로부터 ~7-8 m
# T2: L1/L2 중간 지점 기준 ~10-12 m
# T3: L2로부터 ~9-10 m
```

#### Step 2: 노드 실행

```bash
# 터미널 1: LiDAR 드라이버 실행 (이미 기동 중이면 생략)
ros2 launch ouster_ros driver.launch.py

# 터미널 2: lidar_calib 노드 실행
ros2 launch lidar_calib lidar_calib.launch.py
```

#### Step 3: 패널 검출 확인 (선택)

RViz2에서 포인트 클라우드를 시각화하여 패널이 명확히 보이는지 확인한다.

```bash
rviz2 -d /path/to/lidar_calib/rviz/lidar_calib.rviz
```

- `/lidar_calib/merged_cloud` 토픽에서 두 클라우드가 겹쳐 표시됨
- 패널 클러스터가 밝은 반사 포인트로 식별되어야 함

#### Step 4: 누적 대기

```bash
# 로그에서 누적 프레임 수 확인 (10~30 프레임 권장)
ros2 topic echo /rosout | grep "누적"
```

10 Hz 센서 기준 약 **2~3초** 후 캘리브레이션 실행을 권장한다.

#### Step 5: 캘리브레이션 실행

```bash
ros2 service call /lidar_calib/plane_calibration std_srvs/srv/Trigger
```

정상 출력 예시:

```
response:
  success: True
  message: "패널 캘리브레이션 성공  중심잔차=0.008234 m/패널
            x=-14.9987 y=-2.9998 z=0.0012
            roll=-0.0003 pitch=0.0002 yaw=3.1419 rad"
```

#### Step 6: 품질 확인

RViz2에서 `/lidar_calib/merged_cloud`를 확인한다.

| 지표 | 판정 기준 | 비고 |
|------|---------|------|
| 중심 잔차 | < 0.015 m/패널 | 로그의 `중심잔차` 항목 |
| 법선 각도 | < 1.0° | 로그의 `법선각도` 항목 |
| yaw | ≈ π (3.14159) | 두 센서가 반대 방향 장착 |
| roll, pitch | < 0.01 rad | 지상 차량 정상 범위 |

RViz2에서 두 클라우드의 패널 포인트가 겹쳐 보이면 성공이다.

#### Step 7: 결과 저장

```bash
ros2 service call /lidar_calib/save_calibration std_srvs/srv/Trigger
# → /tmp/lidar_calib_result.yaml 저장
```

저장 파일 확인:

```bash
cat /tmp/lidar_calib_result.yaml
```

출력 예시:

```yaml
lidar_extrinsic:
  parent_frame: "os_sensor"
  child_frame:  "os_sensor2"
  translation:
    x: -14.99870000
    y: -2.99980000
    z:  0.00120000
  rotation_rpy:
    roll:  -0.00030000
    pitch:  0.00020000
    yaw:    3.14190000
```

#### Step 8: 반복 검증 (권장)

3회 반복 실행하여 결과의 재현성을 확인한다.

```bash
# 누적 초기화 후 재실행: 노드 재시작 또는 서비스 재호출
for i in 1 2 3; do
  ros2 service call /lidar_calib/plane_calibration std_srvs/srv/Trigger
  sleep 5
done
```

3회 결과의 표준편차:
- x, y, z: < 5 mm
- yaw: < 0.05°

## 6. 파라미터 참조

`config/params_ouster.yaml`의 `Panel Calibration` 섹션:

| 파라미터 | 기본값 | 설명 |
|---------|-------|------|
| `panel_size` | 1.5 m | 패널 한 변 길이 |
| `panel_size_tolerance` | 0.35 m | 크기 허용오차 (원거리에서 bbox 일부만 관측) |
| `panel_cluster_tolerance` | 0.40 m | 클러스터링 거리 (OS1-32 13 m 빔간격 ~330 mm) |
| `panel_min_cluster_size` | 8 pts | 클러스터 최소 포인트 수 |
| `panel_max_cluster_size` | 3000 pts | 클러스터 최대 포인트 수 |
| `panel_plane_inlier_min` | 0.65 | RANSAC 평면 inlier 최소 비율 |
| `panel_min_distance` | 3.0 m | 센서 원점으로부터 최소 거리 |
| `panel_detection_voxel_size` | 0.05 m | 패널 검출용 voxel 크기 |

### 파라미터 튜닝 가이드

**패널이 검출되지 않을 때**

```yaml
# cluster_tolerance를 늘린다 (빔 간격이 더 클 때)
panel_cluster_tolerance: 0.50   # 기본 0.40 → 0.50

# inlier 기준을 낮춘다 (반사율이 낮거나 경사 배치 시)
panel_plane_inlier_min: 0.55    # 기본 0.65 → 0.55

# 최소 포인트 수를 낮춘다 (원거리 패널)
panel_min_cluster_size: 5       # 기본 8 → 5
```

**환경 노이즈로 오검출이 많을 때**

```yaml
# inlier 기준을 높인다
panel_plane_inlier_min: 0.75

# 크기 허용오차를 줄인다
panel_size_tolerance: 0.20
```

## 7. 문제 해결

### 패널 검출 실패 — LiDAR1=0개, LiDAR2=0개

| 원인 | 확인 방법 | 조치 |
|------|---------|------|
| 패널이 범위 밖 | RViz2에서 클라우드 확인 | `min_range` / `max_range` 파라미터 확인 |
| cluster_tol 부족 | 로그의 클러스터 크기 분포 확인 | `panel_cluster_tolerance` 증가 |
| 반사율 부족 | 패널 반사 포인트 수 확인 | 패널을 더 가까이 이동 또는 교체 |
| 패널 뒷면 배치 | 법선 방향 확인 | 패널을 180° 회전하여 앞면이 센서를 향하게 |

### 잔차가 크다 (> 30 mm/패널)

| 원인 | 확인 방법 | 조치 |
|------|---------|------|
| 패널 직선 배치 | 로그의 `법선 다양성 (cross norm)` 확인 | T1·T3를 Y 방향으로 더 이동하거나 각도 조정 |
| 패널 매칭 오류 | 로그의 `최적 순열` 확인 | 패널 간격을 더 불균일하게 배치 |
| 포인트 수 부족 | 누적 프레임 수 확인 | 30프레임 이상 누적 후 실행 |
| 패널 흔들림 | 거치대 고정 상태 확인 | 거치대를 지면에 고정 |

### roll/pitch가 비정상적으로 크다 (> 0.05 rad)

SVD 단계에서 법선 방향 오염이 있는 경우이다. 지상 구속이 자동 적용되므로  
최종 결과의 roll/pitch는 ≈ 0이 되어야 한다.  
SVD 결과의 roll/pitch가 크게 보고될 경우 법선 다양성 부족이 원인이다.

### 두 클라우드가 RViz2에서 크게 어긋난다

