# plane_calibration 버그 수정 이력

dual OS1-32 LiDAR extrinsic calibration (`/lidar_calib/plane_calibration`)의
개발·검증 과정에서 발견된 문제와 적용된 수정 내용을 기록한다.

---

## 1. Ry(π) 퇴화 해 — SVD가 오답 선택

### 현상
패널 3장을 world x = {−2, 0, +2} 에 배치했을 때 캘리브레이션 결과가
`x=-0.019, y=11.960, yaw=-3.139 rad` 로 출력되어 실제 배치(x≈+16 m)와 전혀 달랐다.

### 원인
두 센서의 중간점 x=0 을 기준으로 패널 x좌표가 좌우 대칭이면,
Ry(π) 회전 + 약간의 평행이동이 올바른 해(단순 x 평행이동)보다
Kabsch SVD 잔차를 더 낮게 만드는 수치적 퇴화가 발생한다.

- LiDAR1(x=−8)이 보는 패널 x집합: {3, 8, 10}
- LiDAR2(x=+8)이 보는 패널 x집합: {10, 8, 6}
  → Ry(π) 적용 후 {−10, −8, −6} → 부호 반전 후 {10, 8, 6} ← LiDAR1 집합과 동일 → 퇴화

### 조치
패널 배치 x좌표를 비대칭(예: {−5, 0, +2})으로 변경하여 Ry(π) 매핑이 깨지도록 한다.

```
[잘못된 예] world x = {-2, 0, +2}  → L1={6,8,10}  L2-negated={6,8,10}  → 퇴화!
[올바른 예] world x = {-5, 0, +2}  → L1={3,8,10}  L2-negated={6,8,13} → 정상
```

`config/params_general_3m_test.yaml` 의 주석에 금지 배치 예시를 명시했다.

## 2. x축 9 cm 오차 — 기울어진 패널의 중심 편향

### 현상
패널을 약 25° 기울여 배치했을 때 x 결과가 15.91 m로 목표(16.0 m) 대비 9 cm 오차가 발생했다.

### 원인
PCL `compute3DCentroid`는 포인트 개수 가중 평균이다.  
기울어진 패널은 가까운 쪽 엣지에 LiDAR 빔이 조밀하게 맞고,
먼 쪽 엣지에 희박하게 맞아 무게중심이 가까운 쪽으로 편향된다.  
특히 LiDAR2가 반대편에서 바라보면 편향 방향이 반대가 되어 오차가 증폭된다.

### 조치
**① bounding box 중심으로 교체** (`detectPanels`)  
RANSAC 평면 좌표계(법선축 n, 수직축 u, v)를 구성하고,
인라이어 포인트의 u·v 범위의 중간값을 중심으로 사용한다.
포인트 밀도 편향이 제거되어 패널 기하 중심에 정확히 수렴한다.

**② 가중 Kabsch SVD** (`solvePlanesToPlanes`)  
각 패널의 가중치를 `min(n_inliers_L1, n_inliers_L2)`로 설정해
원거리·희박 패널의 영향을 줄인다.

**③ face-on 배치 권장**  
패널을 정면(법선이 정확히 센서 방향)으로 세우면 기울기에 의한
샘플링 편향 자체가 없다.

## 3. Face-on 패널 → SVD 퇴화 — yaw 신뢰 불가

### 현상 (1차)
패널 3장을 모두 face-on(법선 = (0,−1,0))으로 세웠을 때:

```
SVD 결과: x=16.115  z=3.591  pitch=-0.432 rad  yaw=0.001 rad
[지상구속]: x=16.014  z=-0.017  yaw=0.0015 rad
결과: x=16.014  (오차 14 mm)
```

### 현상 (2차 — 같은 배치, 다른 실행)
동일 face-on 배치에서 재실행 시:

```
SVD 결과: x=16.022  pitch=-0.000 rad  yaw=0.002 rad   ← pitch 작아서 퇴화 미감지!
[지상구속]: x=16.018  y=0.016  yaw=0.0019 rad
결과: x=16.018  y=0.016  (오차: Δx=18 mm, Δy=16 mm)
```

### 원인
모든 패널 법선이 동일하면 Kabsch SVD의 H 행렬이 rank-1이 된다.  
null-space에 해당하는 특이벡터는 수치적으로 매 실행마다 달라지며,  
추출된 yaw도 0이거나 0.002 rad이거나 비결정론적으로 달라진다.  
`|pitch|>0.05` 조건만으로는 pitch≈0인 경우를 놓친다.

### 조치
**감지 조건을 `normal_span < 0.05` 로 교체** — 원인(법선 다양성 부족)을 직접 판단:

```cpp
if (normal_span < 0.05f || std::abs(kr) > 0.05 || std::abs(kp) > 0.05) {
    RCLCPP_WARN(..., "SVD 퇴화: yaw=0 강제 적용");
    kyaw = 0.0;
}
```

kyaw=0이면 지상구속에서 R=Identity로 패널 중심 차분 평균을 직접 계산하므로
x = avg(Δx_panel) ≈ **16.005 m (5 mm 오차)**, y ≈ 0 으로 수렴한다.

> **적용 조건**: 지상차량의 두 센서가 yaw 오정렬 없이 장착된다는 설계 전제에 의존한다.  
> 실차에서 yaw 오정렬이 ±3° 이상 있을 경우 패널을 기울여 법선 다양성을 확보해야 한다.

## 4. ICP가 z 결과를 악화 — face-on 배치 시 z 미구속

### 현상
SVD + 지상구속 후 z=−0.017 m 이었으나,
ICP 정제 후 z=−0.113 m 으로 오히려 악화되었다.

```
[지상구속]: x=16.014  z=-0.017
[ICP 정제]: x=16.024  z=-0.113  score=0.00712
결과: x=16.024  z=-0.113
```

### 원인
ICP는 클라우드 형상 전체를 정합하여 T를 추정한다.  
패널 3장이 모두 동일 y 평면(y=6 m)에 있고, 씬에 바닥면(z=0 부근)이 없을 때,
ICP에 z 방향 형상 차이가 없어 z 자유도가 미구속(unconstrained)이 된다.  
결과 z는 포인트 잡음에 의한 임의값이다.

### 조치
**법선 다양성(normal_span)을 기준으로 ICP 적용 여부를 분기한다:**

- `normal_span < 0.05` (face-on): ICP 건너뜀 → 지상구속 결과 유지
- `normal_span ≥ 0.05` (기울어진 패널): ICP 실행하되 z는 패널 중심 간 z 차분으로 덮어씀

```cpp
if (normal_span >= 0.05f) {
    // ICP 실행 후 z override
    iz_panel = avg(use1[i].z - use2[perm[i]].z);
    result_T(2,3) = iz_panel;
} else {
    // face-on: ICP 건너뜀
}
```

## 5. yaw 측정 불가 — face-on 배치의 근본 한계

### 현상
face-on 패널 3장(normal_span=0) 배치에서는 yaw=0 강제 적용.  
실차에서 센서 장착 시 발생하는 yaw 오정렬을 전혀 검출할 수 없다.

### 원인
모든 패널 법선이 동일한 방향이면 법선 Kabsch의 H 행렬이 rank-1이 되어
yaw를 포함한 모든 회전 자유도가 미결정 상태가 된다.  
항만 AGV에서 두 LiDAR의 yaw 오정렬은 포인트클라우드 수평 정렬에 직접 영향을 미치므로
반드시 측정되어야 한다.

### 해결 원리 — 수평 방향 법선 다양성 확보

패널을 수평축(yaw)으로 회전시키면 법선이 xy 평면 내에서 다양해진다.

```
H = Σ w_i · n_L1_i · n_L2_i^T
  = diag( 2sin²θ/3,  (1+2cos²θ)/3,  0 )   (중앙 face-on + 좌우 ±θ 배치 시)
```

- z행/열 = 0 → SVD가 순수 yaw 회전만 반환 (pitch=roll=0 정확)
- σ₁ = 2sin²θ/3,  σ₂ = (1+2cos²θ)/3 → θ ≠ 60° 이면 σ₁ ≠ σ₂ → yaw 유일 결정

**normal_span = 2 sinθ (1−cosθ) ≥ 0.05** 가 코드 내 yaw 측정 허용 조건:

| 좌우 패널 yaw 각도 θ | normal_span | yaw 측정 |
|---------------------|------------|---------|
| 20° | 0.041 | 불가 (강제 0) |
| 25° | 0.079 | 가능 (최소) |
| **30°** | **0.134** | **가능 (권장)** |
| 45° | 0.586 | 가능 |

### 권장 배치

```
         Y(전방)
         ↑
  ■ 패널C            ■ 패널B
 (-3, 6, 22)        (2, 6, 22)
  yaw = -30°         yaw = +30°
          ■ 패널A  (0, 6, 22)
            yaw = 0° (face-on)

← LiDAR_front(-8,0,20) ──── LiDAR_rear(+8,0,20) →
```

- **패널A** face-on: x·y·z 구속
- **패널B** +30° 수평 회전: yaw 구속 추가
- **패널C** −30° 수평 회전: yaw 구속 보강

Ry(π) 퇴화 체크: 법선 매핑은 성립(B↔C 교환)하나 center x 잔차 ≈ 1 m → 올바른 해 선택 ✓

### 코드 동작 (변경 불필요)

```
normal_span(±30°) ≈ 0.134 ≥ 0.05  →  yaw=0 강제 조건 불만족
SVD 반환: pitch=0 정확 (수평 법선만 있으면 H[2,2]=0 → 순수 yaw)
→ kyaw = SVD 측정값 사용  (강제 0 아님)
```

`normal_span ≥ 0.05` 이면 ICP도 실행되며, z는 패널 중심 차분으로 덮어쓴다.

## 최종 결과

수정 후 face-on 패널 3장(world x={−3, 0, +2}) 테스트 (3회 반복):

```
1회: x=16.0033  y=0.0002  z=-0.0185  yaw=0.0000 rad  (Δx=3.3 mm)
2회: x=16.0038  y=0.0001  z=-0.0188  yaw=0.0000 rad  (Δx=3.8 mm)
3회: x=16.0057  y=0.0001  z=-0.0201  yaw=0.0000 rad  (Δx=5.7 mm)
```

목표였던 **x·y 1 cm 미만** 달성.  
z 오차(~20 mm)는 OS1-32 수직 빔 이산화의 물리적 한계(10 m에서 빔 간격 ≈ 12~19 cm).  
yaw는 face-on 배치에서 강제 0 — 실차 적용 시 ±30° 배치로 실측 필요.
