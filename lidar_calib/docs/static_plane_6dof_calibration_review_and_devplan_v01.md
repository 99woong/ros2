# 정지 평면타겟 기반 Dual-LiDAR Extrinsic Calibration — §9 검증 결과 검토 및 개발계획

**문서 버전**: v0.2 (SVD 방식 타당성 재확인, Roll/Pitch/Z 목표달성 실행계획 반영)
**작성일**: 2026-07-20
**검토 대상**:
- `rtk_lio_dual_lio_extrinsic_calibration_procedure_v01.md` §9 (정지 평면타겟 기반 6-DOF 방법)
- `isaac_sim/plane_lidar_calibration_260612.usda` (테스트 씬)
- `src/lidar_calibration_node.cpp` `/lidar_calib/plane_calibration` 서비스 (`srvPlaneCalibrate`, `solvePlanesToPlanes`, `detectPanels`)
- `docs/test_report_260612.pdf`, `docs/PLANE_CALIBRATION.md`, `docs/plane_fix.md`

**결론 요약**: §9는 "정지 평면타겟으로 완전 6-DOF가 가능하다"고 결론짓지만, 실제로 검증된 것은 **X/Y/Yaw
3-DOF뿐**이다. Roll/Pitch는 "측정이 안 된 것"이 아니라 **① 테스트에 쓴 타겟 배치가 기하학적으로 애초에
관측 불가능하고, ② 코드가 관측 가능 여부와 무관하게 무조건 0으로 강제하며, ③ 테스트 시나리오 자체에
검출해야 할 roll/pitch 오차가 주입되어 있지 않았다** — 세 가지가 겹쳐서 생긴 결과다. Z는 "측정 안 됨"이
아니라 **20~27mm의 계통 오차(바이어스)를 갖고 측정되었고, 이는 목표(10mm)를 초과한다.** 이 문서는 이
세 축(Roll, Pitch, Z)을 목표 수준(≤0.1°, ≤10mm)으로 실제로 끌어올리기 위한 구체적 실행계획을 다룬다.

**계산 도구에 대한 결론(v0.1 대비 수정)**: 이 문제(15m 이격, OS1-32 원거리 저밀도 포인트)에서는
**SVD 기반 평면 정합이 범용 ICP/NDT(`multi_lidar_calibration_ros2`)보다 기술적으로 더 적합**하다.
§9.6이 원래 ICP/NDT를 지정했던 것은 이 노드 개발 이전 시점의 이론적 검토였고, 실측(§1.3)이 그 가정을
반증했다 — 이는 "item 9를 어겼다"가 아니라 **item 9 작성 이후 얻은 실증 데이터로 도구 선택을 올바르게
갱신한 것**이다. 아래 §1에서 이유를 정리한다.

## 1. SVD(평면 기반)이 ICP/NDT보다 이 문제에 적합한 이유

### 1.1 포인트 밀도 요구조건의 차이

ICP/NDT는 두 점군 **전체의 형상**을 정합해야 하므로 충분히 조밀한 대응점이 필요하다. 15m에서 OS1-32
수직 빔 간격은 **~380mm**(`PLANE_CALIBRATION.md:39`)로 매우 성글다. ICP의 점대점 매칭도, NDT의
voxel 분포 매칭도 이런 저밀도에서는 신뢰할 대응을 만들기 어렵다.

반면 평면은 RANSAC으로 방정식(`ax+by+cz+d=0`)을 피팅하므로, 패널 하나에 수십 개(~64개,
`PLANE_CALIBRATION.md:53`) 포인트만 있어도 **법선·중심 추정이 mm 단위로 안정적**이다 — 평면 방정식은
저밀도에서도 잘 구속되지만, 자유형상 정합(ICP/NDT)은 저밀도에서 급격히 불안정해진다.

### 1.2 닫힌 형태(closed-form) 해 vs 반복 지역 최적화

Kabsch SVD는 초기값 없이 전역해를 한 번에 구한다. ICP/NDT는 반복적 지역 최적화라 좋은 초기값이 없으면
(15m 이격·시야 비중첩 조건에서는 초기값 확보 자체가 어려움) 나쁜 지역해로 수렴하거나 발산한다.
`test_report_260612.pdf`의 "구현방안" 항목에 명시된 **"범용 ICP/NDT 정합 한계로 R/T 정합실패 및 오차
심화 — 전방,후방 LIDAR 원거리(15m)에 의한 ICP 점대점 및 NDT 분산성능 매칭 성능 저하"**가 이 현상을
실측으로 이미 확인한 근거다.

### 1.3 현재 코드도 "SVD 우선, ICP는 보조"로 이미 하이브리드 구현되어 있음

`srvPlaneCalibrate`는 SVD로 먼저 강건한 초기해를 구한 뒤(`lidar_calibration_node.cpp:1296`), 법선
다양성이 충분한 경우에 한해서만 그 결과를 초기값으로 `runICP`를 보조적으로 돌린다(`:1387` 이하). 즉
"SVD 단독 vs ICP 단독" 선택 문제가 아니라 **"SVD가 먼저 있어야 ICP도 국소 정제 도구로 쓸 수 있다"**는
관계다 — SVD의 강건한 초기값 없이 `multi_lidar_calibration_ros2`(ICP/NDT)를 단독으로 돌렸다면 애초에
수렴 자체가 안 됐을 가능성이 높다.

**따라서 이후 개발계획은 `multi_lidar_calibration_ros2`로의 전환이나 교차검증을 목표로 하지 않는다.**
현재의 SVD+조건부 ICP 정제 아키텍처를 유지한 채, 아래 §3의 구체적 개선으로 Roll/Pitch/Z를 목표 수준까지
끌어올리는 것을 목표로 한다.

## 2. 왜 지금 Roll/Pitch/Z가 목표에 못 미치는가 (원인 재정리)

### 2.1 Roll/Pitch — 세 가지 원인이 중첩

1. **타겟 배치의 기하학적 미관측성**: 테스트에 쓴 패널 3개(`plane_lidar_calibration_260612.usda:545-572`)
   가 전부 수직이고 회전은 z축(yaw) 성분만 가진다 — 즉 세 법선이 모두 수평면(XY)에 있다. `docs/plane_fix.md:159-164`
   가 수식으로 증명하듯, 이 경우 Kabsch SVD의 특징행렬 `H = Σ w_i·n1_i·n2_i^T`는 **z행/z열이 항상 0**이
   된다 — 코드 버그가 아니라 **이 타겟 구성에서는 수학적으로 roll/pitch가 존재할 수 없다.**
2. **코드가 관측성과 무관하게 무조건 0으로 강제**: `srvPlaneCalibrate`는 raw SVD 6-DOF 결과(`svd_T`)를
   로그로만 남기고(`:1300-1304`) `normal_span` 값과 **무관하게 항상** "지상차량 구속"을 적용해 roll/pitch를
   0으로 덮어쓴다(`:1316-1317`). `docs/PLANE_CALIBRATION.md:115-124`에 "AGV는 평지 주행 → roll≈0,
   pitch≈0 가정 적용"이라고 의도적으로 문서화된 설계다.
3. **테스트 시나리오 자체에 검출 대상 오차가 없음**: 두 OS1의 `quatd xformOp:orient`가 모두 `(1,0,0,0)`
   (항등회전, `:479`, `:500`) — 즉 ground truth 자체가 roll=pitch=0이라 "0을 0으로 맞췄다"는 것 이상은
   증명되지 않는다.

### 2.2 Z — 26.7mm 계통 오차, 원인은 "패널 z 추정의 거리별 신뢰도 차이를 무시한 단순평균"

`srvPlaneCalibrate`의 z override 단계(`lidar_calibration_node.cpp:1416-1432`)를 다시 보면:

```cpp
// z override: 패널 중심 z 차분의 단순 평균 (가중치 없음)
float z_sum = 0.0f;
for (size_t i = 0; i < n; ++i) {
  const size_t j = static_cast<size_t>(best_perm[i]);
  z_sum += use1[i].center.z() - (R_f * use2[j].center).z();
}
const float z_panel = z_sum / static_cast<float>(n);
```

R/t를 구하는 `solvePlanesToPlanes`의 회전·중심 평균은 `w[i] = min(n_inliers_L1, n_inliers_L2)`로
**가중** 평균한다(`:1112-1141`, 원거리·희박 패널의 영향을 의도적으로 낮춤). 그런데 z override 단계는
**이 가중치를 적용하지 않고 단순 평균**한다. OS1-32의 수직 빔 간격은 거리에 비례하므로(§9.4 표,
`PLANE_CALIBRATION.md:35-39`), 15m 거리의 패널일수록 z 추정 자체의 양자화 편향이 크다. 단순 평균은
이 "편향이 큰 패널"과 "편향이 작은 패널"을 동등하게 반영해 전체 z에 계통 오차를 남긴다. 이는 코드
한 곳만 고치면 되는 **즉시 개선 가능한 지점**이다.

## 3. 개발 계획 — Roll/Pitch/Z를 목표 수준(≤0.1°, ≤10mm)으로

### Phase 0 — 코드: Ground Constraint 조건부화 (§2.1의 원인 ②)

- [ ] 파라미터 `assume_ground_vehicle` (기본값 `true`, 하위호환 유지) 추가.
- [ ] 관측성 지표를 `normal_span`(수평 성분 다양성만 봄) 대신 **H 행렬의 특이값 3개(σ₁≥σ₂≥σ₃) 비율
      `σ₃/σ₁`**로 확장 — 현재 지표는 z행/열이 0인지만 암묵적으로 보고 있어 roll/pitch 관측성 진단에는
      원천적으로 못 쓴다. `σ₃`가 충분히 크다는 것 자체가 "3축 모두 결정 가능"의 직접적 증거다.
- [ ] `assume_ground_vehicle=false`이고 `σ₃/σ₁`이 임계값(예: 0.1) 이상이면 `:1316-1317`의 강제 대입을
      생략하고 `svd_T`(raw 6-DOF)를 그대로 사용.
- [ ] 서비스 응답에 "roll/pitch 관측성: 충분/부족(σ₃/σ₁=...)" 진단 추가 (현재는 로그에만 있음).

### Phase 1 — 지면(ground plane)을 4번째(사실상 1순위) 타겟으로 추가 (§2.1의 원인 ①, 최우선 권장)

**이것이 Roll/Pitch와 Z를 동시에 목표 수준으로 끌어올리는 가장 효과적인 단일 조치다.**

**근거**:
- §9.4 원문이 애초에 "정면 벽 + 측면 벽 + **지면**" 조합을 요구했다 — 지금까지 지면이 빠져 있었다.
- 지면 법선은 정확히 `(0,0,1)` — 기존 수직 패널들의 수평 법선과 **직교**하므로, H 행렬의 z행/열을
  채워 σ₃를 0에서 벗어나게 하는 데 이상적이다 (다른 어떤 타겟보다 효율적으로 관측성을 확보).
- 지면은 **1.5m 패널보다 훨씬 넓은 영역**에서 관측된다 — RANSAC 평면 피팅의 법선 정밀도는 관측
  영역의 크기(레버암)에 비례해 좋아지므로, 지면 평면의 법선 추정 정밀도는 어떤 패널보다도 높다.
  이는 roll/pitch 추정 정밀도를 직접 끌어올린다.
- 지면은 **센서에 가까운 영역**(수 m 이내)도 포함해 관측할 수 있다 — 가까운 거리는 빔 간격이 좁아
  z 추정의 양자화 편향이 작다. 즉 지면 기반 z 참조는 §2.2의 "원거리 패널 편향" 문제를 구조적으로
  피해간다.
- Isaac Sim에는 이미 `GroundPlane`(`plane_lidar_calibration_260612.usda:408-441`)이 있어 별도 자산
  제작 없이 즉시 검증 가능.

**구현 항목**:
- [ ] `detectPanels`와 별개로 `detectGroundPlane(cloud)` 함수 추가: 근거리 대역(`min_z`~`min_z+0.3m`
      정도)에서 RANSAC(`SACMODEL_PLANE`)으로 지면을 피팅, 법선을 센서 기준 위쪽(`+Z` 방향)으로 정규화.
      기존 패널 클러스터와 겹치는 포인트는 사전에 제외(패널은 이미 `detectPanels`가 사용).
- [ ] 지면 평면을 `PanelTarget`과 동일한 구조체(`{center, normal, inlier_ratio, n_inliers}`)로 만들어
      `panels1`/`panels2` 배열에 추가 항목으로 편입 — 기존 순열 탐색·가중 SVD 로직을 그대로 재사용.
      지면은 포인트 수가 압도적으로 많으므로 `w = min(n_inliers_L1, n_inliers_L2)` 가중치 체계에서
      자연히 가장 큰 가중치를 받는다(추가 튜닝 불필요).
- [ ] `solvePlanesToPlanes`의 순열 탐색은 "패널까리는 서로 자리를 바꿔도 되지만 지면은 항상 지면과만
      대응"해야 하므로, 지면 항목은 순열 탐색에서 제외하고 고정 대응으로 별도 처리 (구현 시 주의 필요).

### Phase 4 — 실차 검증 준비

Isaac Sim은 완벽한 시간동기화, 균일한 반사율, 진동 없는 정지 상태, (지면의 경우) 완벽한 평면을
가정한다. 실제 항만 환경 반영이 필요하다.

- [ ] 포장면(아스팔트/콘크리트) 평탄도 확인 — 단, 본 절차는 두 라이다가 **같은 지면 패치**를 보고
      상대 비교만 하므로, 지면이 완벽히 평평하지 않아도 국소 평탄성만 확보되면(예: 요철 없는 5~10m
      구간) 큰 문제가 되지 않는다. 다만 사전에 해당 구간의 실측 평탄도를 확인해 둔다.
- [ ] 패널 반사율(도장/합판 vs 역반사 코팅)에 따른 인라이어 비율 변화 확인.
- [ ] 항만 특유의 진동(인접 크레인/장비 가동)이 "완전 정지" 전제를 얼마나 깨는지 확인.
- [ ] 두 OS1 인스턴스 간 PTP 동기화 적용 여부 확인.
